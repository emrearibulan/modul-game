# Design Specifications

This folder holds design specifications owned by ChatGPT.

## Ownership

- DESIGN — ChatGPT: Owns player-facing design intent, acceptance criteria, reference interpretation, and design QA.
- PO DECISION: Approves scope, priority, and unresolved tradeoffs.
- DEVELOPMENT — Codex: Consumes approved specifications for implementation.

## Required Specification Shape

Each design specification should include:

- Status marker: PO DECISION, DESIGN — ChatGPT, READY FOR CODEX, or BLOCKED.
- Player fantasy or problem statement.
- Player-facing behavior.
- Inputs, outputs, and feedback.
- Acceptance criteria.
- Design QA questions.
- Dependencies and blockers.

## Initial Needed Specs

- BLOCKED: MVP encounter design.
- BLOCKED: MVP module taxonomy.
- BLOCKED: Physical attachment rules.
- BLOCKED: Placement interaction rules.
- BLOCKED: Damage and module loss rules.
- BLOCKED: Ship visual readability rules.

## Ready Rule

READY FOR CODEX means a specification is clear enough for Codex to implement without inventing product design.
